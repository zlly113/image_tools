# 代码审计报告（2026-10-27）

> 审计范围：前端（`index.html`、`js/`、`admin/`）、后端（`server/`）、部署配置（`nginx.conf.example`、`sw.js`、`manifest.json`、`requirements.txt`）、测试与仓库状态。
> 审计方式：逐文件静态审计 + 本地可执行验证（FastAPI TestClient 临时库、Node/pdf-lib 验证、现有测试）。
> 本次审计未改动任何业务源码；仅新增本报告。

---

## 0. 结论摘要

项目功能覆盖面很广，前端“本地处理 + 可选后端”的方向是合理的；扣费 CAS 的核心事务逻辑、密码哈希、Refresh Token 哈希存储、广告渲染的转义等局部实现质量不错。

但当前状态**不适合直接上线**，主要风险集中在四类：

1. **部署面**：按仓库自带的 Nginx 模板部署，整个项目根目录会被当作静态站点根，`.env`、`data/*.db`、`server/` 源码、根目录 zip 备份都可被直接下载；同时默认/占位密钥未拦截，`setup-admin` 可在全新库上被匿名接管。
2. **供应链与文件处理**：PDF.js 3.11.174 含 CVE-2024-4367（恶意 PDF 可在页面主线程执行任意 JS）；PDF 元数据/文件名直接进入 `innerHTML`，形成存储型 XSS。
3. **认证与限流**：`X-Forwarded-For` 被无条件信任，登录/管理员防爆破可被任意绕过；登出在 access token 过期时不会吊销会话；Refresh Token 不轮换。
4. **产品闭环**：点数扣费前端从未调用（`chargeTool` 无引用），后台定价/公告/维护模式/功能开关大量是“死配置”；Phase 2a 的点数体系目前基本是装饰。

此外还有明显的性能问题：首屏同步加载约 4–6MB 第三方脚本，OCR 首次实际下载约 **64.6MiB**，Tailwind 使用运行时 Play CDN，PDF/OCR 大文件缺少内存上限。

**问题数量（按本报告口径）**：P0 阻断/严重 8 项；P1 高 18 项；P2 中 20+ 项；工程/优化建议另列。

## 1. P0：上线前必须修复

### P0-1 按自带 Nginx 模板部署会泄露 `.env`、数据库和源码

- 位置：[nginx.conf.example](nginx.conf.example#L133-L140)、[README.md](README.md#L77-L82)
- 证据：`location / { root $project_root; try_files $uri $uri.html $uri/ /index.html; }`，全文件没有 `location ~ /\.`、`/data/`、`/server/` 的拒绝规则。Nginx 默认不拦点文件，`try_files` 会直接命中真实文件。
- 可被直接下载的示例：`/.env`（`ADMIN_TOKEN`、`JWT_SECRET`）、`/data/toolbox.db`（含 `password_hash`）、`/server/core/config.py`、`/create_admin.py`、`/image_tools_full.zip`（约 40MB）、`/.git/config`（如果服务器上保留了 `.git`）。
- 影响：密钥泄露即管理员完全接管；数据库泄露可离线爆破密码；源码与备份包泄露进一步扩大攻击面。
- 修复：
  1. 静态根改为独立的 `public/`（只放 `index.html`、`js/`、`models/`、`locales/`、`icons/`、`sw.js` 等），后端代码与 `data/` 放在 Web 根之外。
  2. 至少补：`location ~ /\.(?!well-known) { deny all; }`、`location ^~ /data/ { deny all; }`、`location ^~ /server/ { deny all; }`、`location ~* \.(zip|bak|sql|db|py|md|pdf)$ { deny all; }`。
  3. 删除根目录下的 `*.zip`、`patch_*.zip`、`scratch/`；部署包不要在站点根目录生成。
  4. 上线后立即用 `curl -I https://<域名>/.env`、`/data/toolbox.db`、`/server/main.py` 自查。

### P0-2 默认/占位密钥 + 公开引导接口导致管理员被匿名接管

- 位置：[server/core/config.py](server/core/config.py#L13-L14)、[:46-53](server/core/config.py#L46-L53)、[:78-99](server/core/config.py#L78-L99)；[server/api/deps.py](server/api/deps.py#L82)；[server/api/v1/auth.py](server/api/v1/auth.py#L147-L175)；[.env.example](.env.example#L19-L23)
- 三个独立入口：
  1. **默认静态 Token**：`ADMIN_TOKEN` 默认 `test-admin-secret-token`，`get_admin_user` 直接把它当作 `superadmin`。未配置 `.env` 的部署等于无鉴权。
  2. **模板占位符未被识别**：`.env.example` 让用户填 `your_secure_admin_token_here_replace_me` / `your_secure_jwt_secret_key_here_replace_me`，但 `check_security_config()` 只比对代码内默认值，复制模板后连告警都没有。
  3. **`setup-admin` 只校验邮箱**：全新库上，任何知道 `FIRST_ADMIN_EMAIL`（默认 `admin@hhdzai.top`，且写在公开仓库）的人都能以自己的密码创建 `superadmin`。实测：`POST /api/v1/auth/setup-admin` 返回 200，随后登录 `role=superadmin`。
- 影响：部署完成即可能被接管；这不是“配置建议”，是可复现的提权路径。
- 修复：
  - 生产环境启动时若发现默认值或模板占位符，直接 `raise RuntimeError` 拒绝启动；未显式配置 `ADMIN_TOKEN` 时默认关闭静态 Token 后门。
  - `setup-admin` 改为 CLI 生成一次性 token（或仅允许本机调用），并校验邮箱所有权；初始化完成后永久关闭。
  - 删除 `.env.example` 中的真实个人邮箱，改为占位值。

### P0-3 PDF.js 3.11.174 含 CVE-2024-4367（恶意 PDF → 任意 JS）

- 位置：[index.html](index.html#L169)；[js/pdfTools.js](js/pdfTools.js#L235)、[:440](js/pdfTools.js#L440)、[:575](js/pdfTools.js#L575)、[:679](js/pdfTools.js#L679)、[:973](js/pdfTools.js#L973)
- 证据：CDN 固定 `pdf.js/3.11.174`，5 处 `getDocument({ data })` 都没有 `isEvalSupported:false`。该版本（< 4.2.67）在默认配置下会用 `new Function` 编译字体 glyph 指令，恶意 FontMatrix 可注入任意 JS，在主线程执行；页面没有 CSP。PDF 工具的产品定位就是“打开不可信的本地 PDF”。
- 影响：用户拖入一个恶意 PDF，即可在站点同源执行脚本，读取 DOM/localStorage、外传刚打开的文件，直接击穿“本地隐私”承诺。
- 修复：
  - 热修：5 处全部加 `isEvalSupported: false`。
  - 根治：升级 API + Worker 到 `pdfjs-dist >= 4.2.67`（建议当前 5.x），自托管 `/models/pdfjs/`，加入 SW precache，并加版本一致性测试。
  - 补 SRI，或彻底自托管去掉 CDN。

### P0-4 首页 `renderLinks` 存储型 XSS / `javascript:` 链接

- 位置：[js/main.js](js/main.js#L129-L144)
- 证据：`container.innerHTML = links.map(link => \`<a href="${link.url}" ...><i class="fas ${iconClass}">...${title}${desc}\``，`title`、`description`、`icon_class`、`url` 全部原样拼 HTML。后台的广告/外链文案通常来自第三方，标题里写 `<img src=x onerror=...>` 会在所有访客首屏自动执行；`javascript:` URL 点击即执行；`target="_blank"` 也没有 `rel`。
- 影响：只要后台录入一条恶意/被污染的链接，全站访客都会执行脚本；结合同源可调用 `/auth/refresh` 拿 access token，进一步接管普通用户会话。
- 修复：
  ```js
  const esc = s => String(s ?? '').replace(/[&<>"']/g, c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]));
  const safeUrl = u => { try { const x = new URL(u, location.origin); return ['http:','https:'].includes(x.protocol) ? x.href : '#'; } catch { return '#'; } };
  ```
  用 `textContent`/`createElement` 构建节点，`icon_class` 只允许 `/^fa-[a-z0-9-]+$/`，链接补 `rel="noopener noreferrer"`。
- 同类 sink：[js/utils.js](js/utils.js#L15) 的 `toast.innerHTML`（用户名字段可 self-XSS）；[js/main.js](js/main.js#L170-L173) 的语言 `option`；[admin/js/adminApp.js](admin/js/adminApp.js#L832) 的 inline `onclick` JS 上下文转义。建议统一改为 DOM API。

### P0-5 `X-Forwarded-For` 无条件信任，所有限流/防爆破失效

- 位置：[server/api/deps.py](server/api/deps.py#L9-L11)；[server/api/v1/auth.py](server/api/v1/auth.py#L31-L33)；[server/api/v1/analytics.py](server/api/v1/analytics.py#L96-L100)；[nginx.conf.example](nginx.conf.example#L151-L165)
- 证据：代码取 `x-forwarded-for.split(",")[0]`，Nginx 用 `$proxy_add_x_forwarded_for` 把客户端伪造值保留在首段。实测：固定 XFF 第 6 次登录失败被 429；轮换 XFF 连续 8 次全部 401；管理员坏 Token 同样可无限重试；analytics 限流也可绕过。
- 影响：管理员 Token / 用户密码可无限爆破；攻击者还可用受害者出口 IP 作为 XFF，把管理员锁 15 分钟（反向 DoS）。
- 修复：
  - 只信任 `request.client.host`；若必须走代理，配置可信代理 CIDR，并取 XFF **最后一跳**（或使用 `X-Real-IP`）。
  - Nginx 改为 `proxy_set_header X-Forwarded-For $remote_addr;`，不要用 `$proxy_add_x_forwarded_for` 再在应用层取首段。
  - 限流器改为 Redis/数据库等跨进程存储；当前内存限流在多 worker 下阈值 ×N。

### P0-6 管理员调账可把余额打成负数，且可重复入账

- 位置：[server/services/credit_service.py](server/services/credit_service.py#L167-L170)；[server/api/v1/credits.py](server/api/v1/credits.py#L35-L50)；[admin/js/adminApp.js](admin/js/adminApp.js#L866-L893)；[admin/index.html](admin/index.html#L366)
- 证据：
  - `credit_balance = credit_balance + ?` 没有下限，实测 `amount=-100000` 后余额 `-99950`。
  - `RechargePayload.amount` 没有范围校验；`remark` 后端要求 2 字符，前端只判非空。
  - 充值表单同时有 inline `onsubmit` 和 `addEventListener`，确认按钮没有 in-flight 锁；双击发两次 `POST /credits/recharge`，服务端无幂等键。
- 影响：误操作/双击造成余额错账；负数余额破坏“资金守恒”，后续计费全部失真。
- 修复：
  - SQL 改为 `UPDATE users SET credit_balance = credit_balance + ? WHERE id = ? AND credit_balance + ? >= 0`，`rowcount=0` 返回 409。
  - `amount` 加 `ge/le`，整数校验；前端 `confirm` 显示 UID、用户名、金额、原因；提交期间禁用按钮；服务端加 `request_id` 幂等。
  - 统一 `credit_transactions.type` 枚举（当前 `admin_deduct` 不在 schema 注释的枚举里）。

### P0-7 登出在 access token 过期时无效；Refresh Token 不轮换

- 位置：[server/api/v1/auth.py](server/api/v1/auth.py#L108-L132)；[js/authService.js](js/authService.js#L114-L127)
- 证据：
  - `logout` 依赖 `get_current_user`，access token 过期/无效时直接 401，`revoke_user_refresh_tokens` 不会执行；此时 Refresh Cookie 仍有效。实测：过期 Bearer 调 logout → 401；随后 `/auth/refresh` → 200。
  - `logout` 返回 `Response(status_code=204)`，丢弃了注入 `response` 上的 `delete_cookie`；即使正常登出，浏览器里的 `refresh_token` 也不会被清除（服务端已吊销，但 Cookie 仍在）。
  - `/auth/refresh` 只签发新 access token，不轮换 Refresh Token、不检测重放；一个泄露的 Refresh Token 可用满 30 天。
- 修复：
  - logout 允许仅凭 Refresh Cookie 鉴权，或至少在校验失败时也删除 Cookie；返回注入的 `response`，改用 `response.status_code = 204; response.delete_cookie(...)`。
  - Refresh 时 rotate：旧记录 `is_revoked=1` + 新 Cookie；检测“已吊销 token 被重放”则吊销该用户全部会话；每用户会话数上限。
  - 补 `Secure`、`__Host-` 前缀与 `SameSite=Lax`（当前 `secure` 依赖内部 scheme，反向代理/Cloudflare Flexible SSL 下可能丢失）。

### P0-8 注册无限制 + bcrypt 72 字节边界 + 并发注册 500

- 位置：[server/api/v1/auth.py](server/api/v1/auth.py#L16-L60)；[server/core/security.py](server/core/security.py#L8-L10)；[server/services/user_service.py](server/services/user_service.py#L33-L65)；[requirements.txt](requirements.txt#L8)
- 证据：
  - `/auth/register` 无速率限制、无验证码、无邮箱验证；每个账号赠送 50 点，可脚本无限刷；30 次注册实测全部 200。
  - `password` 允许 64 个字符，bcrypt 只接受 72 字节。64 个中文字符 = 192 字节；当前 `bcrypt>=4.1` 会安装 5.0，实测直接抛 `ValueError: password cannot be longer than 72 bytes` → 注册 500；登录则因 `verify_password` 吞异常变成 401，账号永久不可用。
  - 先查后插无 `IntegrityError` 捕获；8 个并发同邮箱注册实测 7 个 `sqlite3.IntegrityError` → 500。
  - 同名 `FIRST_ADMIN_EMAIL` 可被普通注册抢占，随后 `/auth/setup-admin` 因唯一约束 500，初始化流程被破坏。
- 修复：
  - 注册/登录/refresh 加 IP + 邮箱双维度限流、验证码、邮箱验证；验证后才发赠点。
  - 密码按 UTF-8 字节数限制 ≤72，或先 SHA-256 预哈希再 bcrypt；限制 8–64 字符并给中文错误提示。
  - `create_user` 捕获 `IntegrityError` → 409；`setup-admin` 禁止使用已存在的邮箱，改为一次性 token。
  - `bcrypt` 调用是同步 CPU 密集操作，放在 `run_in_threadpool`/`asyncio.to_thread`，否则会阻塞事件循环（见 P1）。

## 3. P2：中优先级（正确性 / 体验 / 可维护性）

### 3.1 后端 / 数据

- **无迁移系统**：[server/models/database_init.py](server/models/database_init.py#L227-L233) 只有 `CREATE TABLE IF NOT EXISTS`；字段/索引变更不会应用到既有库，实测旧表缺列时 `CREATE INDEX` 直接让启动崩溃。引入 Alembic 或版本化 migration 表。
- **分析数据可被污染**：[server/api/v1/analytics.py](server/api/v1/analytics.py#L19-L25) 定义了 `ALLOWED_EVENT_NAMES` 但从未使用；`event_name` 可写任意 HTML 字符串并进入 `daily_stats.feature_stats`；`visitor_id` 客户端自造可刷 UV。强制白名单/签名。
- **分析缓冲丢数据**：[server/api/v1/analytics.py](server/api/v1/analytics.py#L66-L91) 先把 batch 从 buffer 摘除，写入失败即永久丢失，无重试；shutdown 时 `cancel()` 后也可能丢。失败回填 + 退避重试。
- **聚合只回补最近 2 天**：[server/api/v1/analytics.py](server/api/v1/analytics.py#L137-L140) 有历史后只算今天/昨天，停机 3 天造成永久空洞；90 天删除后无法恢复。按日期水位线重算/提供 backfill。
- **`/analytics/overview` 每次全量聚合**：[server/api/v1/analytics.py](server/api/v1/analytics.py#L217-L221)；`days` 无 `ge/le`，`days=-1` 会 `LIMIT -1` 返回全部历史。限制 1–90，聚合移到后台，加缓存/限流。
- **IP 哈希可逆**：[server/api/v1/analytics.py](server/api/v1/analytics.py#L26)、[:41-L45](server/api/v1/analytics.py#L41-L45) 固定 salt + 16 hex，IPv4 空间可离线枚举；改为 HMAC + 随机 salt + 完整长度，或直接不存。
- **管理员层级/最后管理员保护缺失**：[server/api/v1/users.py](server/api/v1/users.py#L40-L58)；[server/services/user_service.py](server/services/user_service.py#L133-L143) 任一 admin 可封禁 superadmin、可禁用自己，`PATCH /users/99999/status` 返回 ok。加角色等级、自禁保护、`rowcount` 检查。
- **审计日志 fail-open**：[server/services/audit_service.py](server/services/audit_service.py#L27-L28) 写入失败只 print；静态 Token 的 `admin_id=0` 被映射为 NULL，所有应急操作无法追溯。审计失败应阻断/落本地 append-only，静态 Token 用独立 `system` 账号。
- **负数/越界流水类型**：[server/services/credit_service.py](server/services/credit_service.py#L175) 写 `admin_deduct`，不在 schema 注释的枚举内；`create_admin.py` 给 99999 点却不写流水。统一枚举并补流水。
- **`DB_PATH` 无目录分量时启动崩溃**：[server/core/database.py](server/core/database.py#L7) `os.makedirs(os.path.dirname("toolbox.db"))` → `FileNotFoundError`。解析为项目绝对路径，或跳过空 dirname。
- **SQLite 性能**：`isolation_level=None` 是 autocommit；analytics 的 50 行 `executemany` 未包事务，默认 `synchronous=FULL` 会 50 次 fsync；每请求新建连接。建议 `PRAGMA synchronous=NORMAL`、批量包 `BEGIN/COMMIT`、连接池/单写队列。
- **CORS 默认含 localhost**：[server/core/config.py](server/core/config.py#L23-L29) 且 `allow_credentials=True`；生产应移除并显式白名单。
- **JWT 未要求 `exp`/`jti`/`aud`**：[server/api/deps.py](server/api/deps.py#L34)、[:95](server/api/deps.py#L95)；无 `exp` 的 token 永不过期，无法吊销。加 `require` 与 token version。
- **`/api/health` 泄露版本/模式**：[server/main.py](server/main.py#L78-L84)；低风险，生产可只返回 `{"status":"ok"}`。
- **`/admin` 显式路由是死代码**：[server/main.py](server/main.py#L92-L95) 先 mount 了 `StaticFiles`，后面两条 `@app.get("/admin")` 不会命中；清理或调整顺序。
- **`nginx` `add_header` 继承失效**：[nginx.conf.example](nginx.conf.example#L51-L54) 的 server 级安全头，被各 location 的 `add_header` 覆盖；`/`、`/api/`、`/s/`、`/js/`、`/models/` 等丢失 `nosniff`/`X-Frame-Options`，全站无 HSTS/CSP。用 `include security-headers.conf`。
- **`nginx` `/admin` 的 `alias` + `try_files` 是已知易错组合**：[nginx.conf.example](nginx.conf.example#L125-L128)；建议 `root` + `index` 或单独验证。
- **短链计数双写/匿名写**：[server/main.py](server/main.py#L144) 与 [server/api/v1/tools.py](server/api/v1/tools.py#L146) 各 +1；广告/外链 click 接口匿名可写，可刷榜。加去重/限流/服务端计数。
- **`/s/{code}` 302 无 `no-store`/`Referrer-Policy`**：短码可被中间层缓存，并作为 Referer 泄露给目标站。
- **短链数据库无归属/过期/删除**：`created_ip` 明文保存，`short_links` 永久增长；加 `user_id`、过期时间、举报/下线接口。

### 3.2 前端核心

- **首屏相对路径 bug**：[index.html](index.html#L2055) 使用 `src="js/main.js?v=3.0"`，而其他资源是绝对路径。纯静态部署的 `/s/<code>` 回退到 `index.html` 时，脚本解析为 `/s/js/main.js` → 404，短链拦截逻辑永远不执行。改为 `/js/main.js`。
- **`importmap` 在 module script 之后**：[index.html](index.html#L148) 的 `tracker.js` 早于 [:172](index.html#L172) 的 importmap；规范要求 importmap 先于任何 module script，部分浏览器会报错/忽略，OCR 的 bare specifier 可能解析失败。把 importmap 移到 `<head>` 最前。
- **Hash/`?lang` 路由未实现**：`manifest.shortcuts` 使用 `#ocr/#bg-remover/#link-tools`，`sitemap` 也列了 hash URL，`hreflang` 使用 `?lang=`，但代码只读 `location.hash` 做 HTTPS 跳转，从未根据 hash/lang 切 tab。带 `?lang=en-US` 的英文页面实际仍按浏览器语言/中文显示。实现 hash/lang 路由，或删除这些声明。
- **`sitemap` 含 hash URL**：不会被搜索引擎当作独立页面；`/index.html` 与 `/` 重复且无 canonical；补 301（非 www → www）与有效 URL。
- **`og:image`/`apple-touch-icon`/manifest 只有 SVG**：社交平台与 iOS 对 SVG 支持差；补 1200×630 PNG、180×180 PNG、192/512 PNG。
- **Tailwind 使用运行时 Play CDN**：[index.html](index.html#L146)、[admin/index.html](admin/index.html#L8) 加载 407KB `tailwindcss.js` 并在浏览器生成 CSS。生产应预编译/ purge，体积可降到几十 KB，并消除 FOUC/CLS。
- **首屏同步阻塞**：head 中 `jszip`、`exif-js`、`pdf.js`、`docx`、`xlsx`、`pdf-lib`、`qr-code-styling`、`jsQR` 全部非 `defer/async`，约 4–6MB；其中 docx/xlsx/pdf.js 只在少数功能用到。按 tab 动态 `import()`，至少加 `defer`；自托管 + SRI。
- **CDN 供应链**：`xlsx` 与 `exif-js` 未锁版本，所有 CDN 脚本无 SRI；`pdf.js` 版本本身有 CVE。自托管到 `/models/` 并锁版本是最彻底的修复。
- **`showToast` 用 innerHTML**：[js/utils.js](js/utils.js#L15)；`user.username` 可含 HTML（self-XSS），错误消息也可能是外部内容。改 `textContent`。
- **广告语言监听器泄漏**：[js/adManager.js](js/adManager.js#L61) 在 `init()` 内注册 `locale-changed` → `this.init()`，每次语言切换都新增一个监听器，导致重复渲染/重复埋点。移到只注册一次。

### 3.3 前端性能 / SEO / 合规

- **首屏体积**：HTML 180KB；应用模块约 250KB；第三方脚本约 4–6MB；Tailwind 407KB 运行时；OCR 首次 64.6MiB。建议预编译 Tailwind、按 tab 代码分割、自托管/延迟 CDN、修 OCR 流量文案。
- **`models/` 约 68MB**：`ort-wasm-simd-threaded.jsep.wasm` 23.86MB、非 jsep 11.79MB、`ort.js` 2.43MB、det/rec 29.7MB。当前 OCR 走 jsep wasm；非 jsep 与 `ort.js` 疑似未使用（需确认后删除，约 15MB）；`models/opencv.js` 等 0 字节历史文件可清理。
- **PWA 离线承诺不完整**：`/js` 缓存优先导致旧代码；docx/xlsx 无 `crossorigin` 被 SW 跳过（离线导出失败）；CMap/标准字体未预缓存；`sw.js` 失败分支 `return null` 不是合法 `Response`。
- **隐私文案与实现不一致**：页面宣称“100% 无需上传/完全离线”，但 `tracker.js` 会上报 visitor/session/设备/来源/哈希 IP；短链后端在 DB 异常时会降级到 `is.gd`；CDN（FontAwesome/JSZip/pdf.js/docx/xlsx）会暴露访客 IP；OCR 模型可能从 ModelScope 下载。隐私政策只泛泛提到“技术日志”，未披露 analytics/第三方 CDN/短链转发。补披露与同意，或改文案。
- **AdSense/GDPR 声明**：隐私政策声明 AdSense 与 GDPR 合规，但页面没有 AdSense 脚本，也没有同意横幅；analytics 在无同意时即上报。若面向欧盟/英国，需先做 consent 再加载。
- **SEO**：`?lang`/hash 未实现，`hreflang`/sitemap 失效；`og:image` 用 SVG；`/index.html` 与 `/` 重复；非 www 未 301；manifest 只有 SVG 图标。逐项修。
- **可访问性**：QR dropzone 是 div + onclick，无键盘支持；tab 无 `role=tab`；toast 无 `aria-live`；admin 弹窗无焦点管理。

## 4. 已验证“不是问题”的点（避免误报）

- **SQL 注入**：所有查询参数化；`LinksService.update_link` 的列名来自 Pydantic 白名单字段。
- **Mass assignment / IDOR / 自助提权**：`AdUpdate`/`LinkUpdate`/`SiteConfigUpdate` 字段与 DB 列一一对应，无 `role`/`credit_balance`；`/credits/*` 使用 token 里的 user id；`/users/*` 全需 admin。
- **路由冲突**：逐条枚举 8 个子路由与 `main.py` 挂载，`/{id}/click` 全为 POST，`/admin/all` 无对应 `GET /{id}`，`/tools/pricing` 不被 `/{tool_key}/use` 覆盖。
- **SQLite 缺少 commit**：`isolation_level=None` 是 autocommit，`save_refresh_token`/`revoke_user_refresh_tokens`/`set_user_status` 等不 commit 也持久化；这是风格不一致，不是当前 bug（但改成显式事务后会变 bug）。
- **生产 docs 关闭**：`/api/docs`、`/api/openapi.json`、`/api/redoc` 在生产返回 404。
- **CSRF**：唯一 cookie 鉴权端点是 `/auth/refresh`，`SameSite=Lax` + POST，跨站 fetch 不携带 cookie，暂不构成 CSRF。
- **扣费 CAS 并发**：`tests/stress_test_cas.py` 在单进程 200 并发下严格扣费 10 次、余额 0、流水 -100，全部通过。
- **PDF API/Worker 版本一致**：CDN 3.11.174 与本地 worker 内部 `3.11.174` 匹配（但仍有 CVE）。
- **i18n 键完整**：zh/en 各 256 个键，`index.html` 217 个 `data-i18n` 键全部存在；HTML 无重复 ID；35 个 inline handler 都能在 JS 中找到定义。
- **广告渲染**：`adManager.js` 有 `escapeHtml` + `sanitizeUrl`，广告侧未发现 `javascript:` 注入。
- **Admin 表格**：广告/外链/用户/定价字段大多已 `escapeHtml`，后台 toast 使用 `textContent`。

3. 修 P1-3/P1-4/P1-7/P1-8（PDF/QR 的 XSS 与可见性）。

### 第 2–4 周：把“能用”变“可靠”
1. 前端：hash/lang 路由、相对路径、importmap 顺序、去重事件绑定、非 2xx 处理、用户分页、定价/配置保存原子性、admin token 续期/登出。
2. PDF/OCR：destroy/cancel、generation token、内存上限、CMap、EXIF 方向、加密 PDF、OCR worker 串行化/下采样/dispose。
3. PWA：build hash/网络优先、模型版本化、单一 cache、修 `Response.error()`、离线能力检测。
4. 后端：迁移系统、审计 fail-closed、管理员层级、配置 schema、分析聚合 backfill/限流、SQLite 事务/同步模式。

### 第 2 个月：性能与工程化
1. Tailwind 预编译 + 代码分割 + 自托管 CDN + SRI；首屏目标 < 1MB、OCR 目标 < 40MB（换非 jsep + 压缩/按需）。
2. 引入 `package.json` + Vite/esbuild、ESLint/Prettier、pytest、Playwright 冒烟、CI；把 `tests/` 从“字符串断言”升级为真实模块测试。

### 明确的“不要做”
- 不要把 `ADMIN_TOKEN` 作为长期共享密钥；不要再把任意后台字段直接拼 `innerHTML`；不要在 `.env` 缺失时“告警后继续启动”；不要把整个仓库根目录作为静态根。
